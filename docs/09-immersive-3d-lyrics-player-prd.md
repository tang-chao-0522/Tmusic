# 沉浸式 3D 歌词播放页：需求与技术方案

> 状态：方案稿，待视觉资产与交互细节确认  
> 日期：2026-10-26  
> 对应入口：侧栏品牌图标 → `/lyrics-stage`  
> 参考：本次对话提供的深色星空、透明唱片、发光歌词播放页截图

> 实施记录（2026-10-26）：第一版已实现。场景使用 React Three Fiber + Three.js；动态歌词采用浏览器 Canvas 生成字形纹理并放入 3D 空间，以确保中文覆盖。下文的 Drei SDF/GLB 是后续视觉升级路线，不是第一版的实际依赖。

## 1. 目标与范围

改造点击品牌图标进入的沉浸歌词页。页面在同一屏内呈现左侧可转动的 3D 唱片装置、中间偏右的空间歌词、下方歌曲信息与播放控制。视觉上采用深蓝暮色、云海与山脉、玻璃与金属材质、粉紫光轨，保留截图的空间感和明暗关系；具体素材与模型由 TMusic 自有资产制作，不把截图当作最终背景图。

本期仅改 `/lyrics-stage` 中央播放内容。左侧应用导航、顶部搜索/头像、右侧“Playing Next”边栏均不新增；现有 `/player` 常规播放页、侧栏结构和全局音频内核不属于本期视觉改造范围。原有返回入口保留。播放队列可继续通过既有功能入口使用，本期不在舞台内复制一列队列。

## 2. 当前实现与复用点

| 现有能力 | 位置 | 本期处理 |
| --- | --- | --- |
| 沉浸歌词路由和品牌图标入口 | `frontend/src/app/App.tsx`、`frontend/src/components/layout/Sidebar.tsx` | 沿用 `/lyrics-stage`，不另建路由 |
| 单句 WebGL 歌词舞台 | `frontend/src/pages/LyricsStagePage.tsx`、`frontend/src/lib/lyricStageRenderer.ts` | 用新场景替换该页视觉层；旧渲染器可保留作低配降级，避免两套动画同时运行 |
| 歌词接口与 LRC 解析 | `frontend/src/lib/queries.ts`、`frontend/src/lib/lyrics.ts` | 沿用；按时间戳决定当前句和邻近句 |
| 播放状态与音频 | `frontend/src/stores/playerStore.ts`、`frontend/src/components/player/PlayerDock.tsx` | 沿用单一状态与音频实例；舞台仅发起播放、切歌、跳转进度等操作 |

## 3. 页面结构与视觉要求

### 3.1 桌面端布局

- 舞台铺满可用视口，背景为静态/低速视差的暮色云海与山景。背景优先采用分层美术贴图；近景少量粒子和光晕由 3D 场景产生。
- 左侧约 45% 为唱片装置：圆形唱片、中心轴、透明方形保护罩、金属底座、细光轨。唱片封面随歌曲变更，播放时缓慢旋转，暂停时停在当前角度。
- 右侧约 45% 为歌词区：当前句在视觉焦点上，字号/亮度/发光强于前后句；前后约 2–3 句沿深度轴递减、轻微倾斜，体现真实空间层级。长句自动换行，不裁掉中文、英文和混排字符。
- 下方独立的操作层包含歌名、歌手、进度时间、进度条、上一首、播放/暂停、下一首，以及现有随机/循环/音量能力中适合舞台的入口。按钮不能被 Canvas 拦截。
- 顶部仅保留返回操作及必要的“歌词”标题/状态，避免截图中导航和右侧队列侵入本期范围。

### 3.2 屏幕适配

- ≥ 1200 px：唱片与歌词左右并列，控制区靠底部。
- 768–1199 px：唱片缩小，歌词保留至少 40% 可读宽度；控制区不压住歌词。
- < 768 px：唱片在上、歌词在下，弱化背景细节和装置粒子；进度条及核心播放按钮始终可见。移动端允许手指在场景区域拖动，但页面的控制区与歌词点击保持独立。
- 使用安全区内边距；横屏和窄屏不得出现横向滚动。

## 4. 功能与交互需求

| ID | 需求 | 验收标准 |
| --- | --- | --- |
| F01 | 入口与返回 | 点击现有品牌图标进入该页；返回原页面，直接访问路由时返回发现页 |
| F02 | 歌曲同步 | 歌名、歌手、封面、时长、播放/暂停随当前曲目更新；切歌后旧歌词不残留 |
| F03 | 空间歌词 | 当前句和前后句在不同 z 深度显示；当前句高亮，句间过渡平滑；中文、英文、混排可读 |
| F04 | 时间同步 | 播放、暂停、seek、切歌后当前句正确；点击带时间戳歌词可 seek；显示时间与音频一致 |
| F05 | 3D 拖动 | 在 3D 舞台空白处按住拖动可改变水平与俯仰方向；水平建议限制在 ±25°、俯仰 ±12°；松手后可缓慢回正或保留角度，以交互样机确定，默认缓慢回正 |
| F06 | 播放控制 | 上一首、播放/暂停、下一首、进度拖动接入现有 store；房间模式按现有权限规则禁用不允许的控制 |
| F07 | 歌词状态 | 无歌曲、加载中、无同步歌词、请求失败分别给出明确状态；无时间戳歌词只展示文本，不伪造逐句同步时间 |
| F08 | 视觉降级 | WebGL 不可用、上下文丢失或性能不足时保留静态封面/背景与 DOM 歌词、控制；音频不中断 |
| F09 | 辅助操作 | Canvas 不是唯一歌词载体；提供可访问的歌词文本、按钮名称、键盘焦点和减少动态效果选项 |

**拖动冲突规则：**仅 3D 视觉区域启动方向拖动；按钮、进度条和可点歌词的 pointer 事件优先。拖动达到阈值后不触发歌词点击。滚轮不默认缩放，以免影响页面与进度操作；可提供“重置视角”按钮。

## 5. 技术路线

### 5.1 推荐技术

| 层 | 技术 | 用途 |
| --- | --- | --- |
| 应用与状态 | 现有 React 19、TypeScript、Zustand、TanStack Query | 路由、歌曲/播放状态、歌词数据，不改音频所有权 |
| 3D 场景 | `three` + `@react-three/fiber` | 透视相机、模型、材质、灯光、场景渲染、拖动事件 |
| 场景辅助 | `@react-three/drei` 按需引入 | SDF 文本、模型加载、受限相机控制；不整包使用高成本效果 |
| 模型与贴图 | Blender 建模 → glTF/GLB；压缩贴图 | 唱片、透明罩、底座等基础几何；封面作为运行时贴图 |
| 控件与无障碍 | HTML/CSS/React DOM | 返回、播放、进度、音量、文本降级与读屏 |

选择 React Three Fiber 是基于现有 React 组件结构做场景拆分、加载和生命周期管理；Three.js 负责真正的 3D 几何和渲染。现有原生 WebGL 歌词着色器擅长单句全屏效果，但要加入可拖动的唱片、相机、多个空间歌词和材质时，继续扩写将明显增加渲染与交互维护成本。这是基于当前代码结构作出的工程判断。

### 5.2 唱片与环境实现

1. **第一版几何**：唱片本体用圆盘/环形几何，保护罩用薄盒与透明材质，底座用环、圆柱、倒角盒；先完成比例、透视、旋转和灯光，再替换为 Blender GLB 资产。
2. **封面与反射**：歌曲封面贴于唱片面；金属边缘用 PBR 材质，玻璃使用低成本透明层与预制反射纹理，避免大面积实时折射。
3. **环境**：山、云、星空主要用分层 2D 图像或远景平面；3D 只承担唱片、近景碎片、少量星点和光轨。截图中的“大型行星 + 广阔山海”不宜全部实时建模。
4. **动画**：唱片旋转跟随播放状态；光轨、微粒轻量循环；暂停和 `prefers-reduced-motion` 下停掉非必要动画。

### 5.3 3D 歌词实现

- 将歌词映射为 `[{timeMs, text, translation?}]`，用二分查找当前句；只渲染当前句及邻近少量句，避免整首歌生成大量纹理/几何。
- 歌词对象置于相机前方的不同 z 坐标，前后句附加小角度旋转、透明度和缩放。拖动相机时歌词与唱片都发生可见视差；将歌词旋转限制在可读范围内。
- 动态中文歌词优先使用 SDF 文字面（`drei/Text`，底层 Troika），叠加偏移的暗色背层、边缘高光和柔和辉光，形成可见厚度与立体光照。它是真正布置在 3D 场景内的多层文本，而不是纯 CSS 透视。若视觉验收要求近距离看到实体字侧面，再针对当前句试做字体网格挤出；整首动态中文逐字挤出需单独做性能和字库验证。
- 对齐歌词时间时使用现有音频引擎时间作为播放中的高频显示参考，store `progressMs` 作为暂停/seek/房间同步状态；不另起计时器累加播放时间。
- 翻译歌词若存在，作为次要文本置于当前句下方；无翻译时留白收紧。歌词点击 seek 仅对真实时间戳开放。

### 5.4 组件与数据流

```text
LyricsStagePage
├─ usePlayerStore / queries.lyrics / parseLyricLines
├─ StageCanvas (React Three Fiber)
│  ├─ EnvironmentLayers
│  ├─ DiscDisplay
│  ├─ SpatialLyrics
│  └─ DragCameraRig
├─ StageControls (DOM，调用既有 playerStore)
├─ StageStatus / accessible lyrics (DOM)
└─ BackButton (DOM)
```

3D 组件只接收当前曲目、歌词索引、播放状态与相机目标值；音频和队列仍由现有播放内核管理。歌词数据解析、activeIndex、时间插值集中在页面级 hook，Canvas 与 DOM 共享同一结果，避免视觉歌词和辅助文本不同步。

## 6. 性能、兼容与资产约束

- 桌面端目标在常见 1080p 设备上稳定 50–60 FPS；移动端目标 30 FPS 以上。以实际目标设备验收，不能仅以开发机结果判定。
- DPR 初始上限建议 1.5，性能不足时降至 1；限制透明层、实时阴影、后期辉光和粒子数量。唱片无动作、歌词不变化且暂停时按需渲染；播放时仅为必要动画持续渲染。
- 场景资产按需加载并显示可操作的加载状态；目标是首屏交互不必等待完整 3D 模型。模型与贴图预算需在视觉资产产出后确定，不能在没有素材规格时承诺固定包体积。
- 处理 WebGL context lost/restored、页面隐藏、窗口 resize、曲目快速切换和资源释放。失去 3D 渲染能力时，DOM 控件与歌词仍可用。
- 正式使用的山海背景、唱片纹理和字体必须有项目可用的授权；参考图仅作为视觉方向。

## 7. 实施顺序与交付物

1. **交互样机**：在现有入口建立两栏舞台、唱片基础几何、空间歌词与拖动视角；验证中文字体、可读性、按钮事件冲突。
2. **视觉资产**：制作 GLB 装置和分层环境图，确定封面映射、玻璃/金属、光轨与颜色；替换样机几何。
3. **播放接入**：连接歌词加载、seek、上一首/下一首、进度、房间模式权限和各类空态；保持单一音频实例。
4. **优化与验收**：按桌面/移动端测帧率、资源加载、WebGL 失效、缩小动态效果和键盘操作；完成视觉与功能回归。

交付包括页面代码、可复用 3D 场景组件、项目自有模型/贴图、降级界面和简短资产说明。当前文档是设计与实施基线，尚未实施 UI。

## 8. 待确认的视觉决策

- 唱片装置是否严格按照截图的“透明方盒 + 光环 + 底座”，还是保留这些元素但用 TMusic 自有风格重新设计。
- 舞台拖动释放后默认缓慢回正；若要固定观察角度，需要在交互样机阶段改为“保持角度 + 重置视角”。
- 参考图出现的“Dolby Atmos / Hi-Res”标识应仅在真实音频能力可验证时显示；本期不按截图直接加标。
