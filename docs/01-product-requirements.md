# TMusic 产品需求文档（PRD）

> 状态：Draft for Review  
> 版本：v0.1  
> 日期：2026-10-03  
> 产品定位：面向个人学习使用，以网易云音乐内容为主要播放源，融合个人音乐库、实时“一起听”、社区评论与 AI 音乐助手的 Web 播放器。

## 1. 文档目标

本文用于统一产品范围、用户流程、业务规则、非功能要求和阶段优先级，作为 UI 设计、技术设计、接口设计和验收测试的共同基线。

本阶段只定义产品和接口，不包含 UI 视觉稿与业务代码实现。UI 稿到位后，需要补充页面线框、组件状态和视觉验收标准。

## 2. 参考项目分析

先做一个范围纠偏：三个项目并非都是“第三方网易云播放器”。Music Claw 以网易云 API 为内容源；Spotify Clone 是自有上传/Cloudinary 媒体的 MERN 示例；Jammify 使用 JioSaavn，并整合 Genius、Spotify 等数据。后两者适合借鉴产品与工程思路，不能直接当作网易云接入实现参考。

### 2.1 Music Claw

参考仓库：[CaiZongyuan/musiclaw](https://github.com/CaiZongyuan/musiclaw)

可借鉴：

- 围绕网易云数据源形成完整播放链路，覆盖首页推荐、搜索、歌单、专辑、歌手、收藏、每日歌曲、私人 FM 和播放队列。
- React 19、TanStack Query、Zustand、Howler.js、Dexie 的职责划分清晰，适合处理服务端数据、播放器瞬时状态和本地持久化。
- 播放器 Dock 常驻、队列独立、从播放器返回来源页面等交互适合作为 TMusic 的基础体验。
- 将网易云 API 作为独立服务，而不是让页面直接耦合第三方接口。

不直接照搬：

- 它是 YesPlayMusic 的等价重写，产品差异化有限；TMusic 的核心差异应是“一起听 + 实时交流 + AI 音乐助手”。
- 部分播放能力依赖浏览器本地网易云会话，不适合作为多端一致身份体系。

### 2.2 Spotify Clone

参考仓库：[LazzouziYoussef/spotify-clone](https://github.com/LazzouziYoussef/spotify-clone)

可借鉴：

- MERN 分层、全局播放器状态、标准播放控制和三栏响应式布局。
- Socket.IO 实时聊天、在线状态、好友当前收听状态，是“一起听”社交侧的良好基线。
- 管理端、统一错误处理中间件、歌曲/专辑/用户/歌单 REST API 的工程化思路。

需要增强：

- “展示好友正在听”不等于“同步听歌”；TMusic 必须定义房主权限、播放时钟、漂移校正、断线重连和房间生命周期。
- 实时事件不能只依赖单实例内存；需要 Redis Pub/Sub 或 Streams 支持多实例扩展。

### 2.3 Jammify

参考仓库：[shreejaybhay/jammify](https://github.com/shreejaybhay/jammify)

可借鉴的产品思路：

- 智能/模糊搜索、同步歌词、个人音乐库、歌单、最近播放、社区帖子与评论。
- 沉浸式全屏播放器、随封面变化的氛围背景、移动端底部导航和 PWA 体验。
- 多来源歌曲匹配、歌单导入和推荐系统为后续 AI Agent 提供了方向。

合规边界：

- 该仓库明确声明仅供查看与学习，禁止未经授权复制、修改、部署或制作衍生项目。TMusic 仅参考抽象产品能力，不复制源码、素材、文案、组件结构或算法实现。

### 2.4 综合结论

| 领域 | 采用方向 | TMusic 的增强点 |
| --- | --- | --- |
| 播放器 | Music Claw 的完整播放链路 | 统一播放内核、队列持久化、源失效降级 |
| 实时社交 | Spotify Clone 的聊天与在线状态 | 房间权威时钟、同步协议、角色权限、重连恢复 |
| 发现体验 | Jammify 的搜索、歌词、社区与氛围感 | 网易云内容适配、搜索聚合、AI 对话式发现 |
| AI | 新增悬浮入口和会话页 | 后续接入 Agent、RAG、工具调用与歌单自动创建 |
| 架构 | React + Node.js + MongoDB | Redis 实时状态/缓存，REST + WebSocket + SSE |

## 3. 产品目标与成功指标

### 3.1 产品目标

1. 用户能顺畅完成“发现—搜索—播放—收藏—建歌单”的个人听歌闭环。
2. 用户能创建或加入听歌房，与其他成员同步播放并实时聊天。
3. 用户能在歌曲、歌单等内容下发表评论并互动。
4. 用户能通过悬浮 AI 球进入对话页；首期完成可替换的对话框架，后续无须重构即可接入 Agent/RAG。
5. 网易云播放源被封装为可替换 Provider，避免核心业务依赖第三方响应结构。

### 3.2 建议指标

| 指标 | MVP 目标 |
| --- | --- |
| 首次可播放时间 P75 | 同地域、缓存命中时不高于 2 秒 |
| 普通 API P95 | 不高于 500 ms（不含第三方源调用） |
| 房间消息端到端 P95 | 不高于 300 ms |
| 同步播放稳态偏差 P95 | 不高于 800 ms |
| WebSocket 断线恢复 | 10 秒内可自动恢复并拉齐状态 |
| 播放失败可解释率 | 100%，不得无限加载 |
| 核心流程前端错误率 | 低于 1% 会话 |

具体阈值需在部署区域、CDN 和网易云接口方案确定后压测校准。

## 4. 用户与角色

| 角色 | 能力 |
| --- | --- |
| 游客 | 浏览公开内容、搜索、试听允许播放的歌曲、查看公开评论；不能发言、收藏、建房 |
| 注册用户 | 完整播放、收藏、歌单、评论、创建/加入房间、AI 会话 |
| 房主 | 管理房间、控制播放、管理成员和协作者、结束房间 |
| 房间协作者 | 在房主授权时切歌、暂停、调整队列 |
| 管理员/运营 | 内容与评论治理、用户处置、查看审计记录和系统状态 |
| AI 服务身份 | 经受限内部接口检索歌曲、生成建议、创建草稿歌单；不可绕过用户确认执行敏感操作 |

TMusic 账户与网易云账户应分离。用户可以绑定网易云会话以获得个性化数据，但 TMusic 的社交身份、评论、歌单和房间数据归属 TMusic 账户。

## 5. 需求范围与优先级

### 5.1 MVP（必须）

- 账户：注册、登录、刷新令牌、退出、个人资料。
- 音乐发现：首页推荐、新歌/排行榜入口、搜索、歌曲/专辑/歌手/歌单详情。
- 播放器：播放/暂停、上一首/下一首、进度跳转、音量、播放模式、队列、歌词、播放错误与重试。
- 个人库：喜欢歌曲、创建/编辑/删除歌单、歌曲增删和排序、最近播放。
- 一起听：创建/加入/离开/结束房间、邀请链接、成员列表、主持人同步控制、房间聊天、断线恢复。
- 评论：歌曲评论与歌单评论、回复、点赞、删除自己的评论、举报。
- AI：全局悬浮波纹球、展开/收起、AI 对话页面、会话列表、流式回复、推荐歌曲卡片占位协议。
- 管理与安全：基础内容治理、限流、审计日志、敏感配置隔离。

### 5.2 P1（重要）

- 网易云账号绑定、每日推荐、私人 FM、网易云歌单导入。
- 好友/关注、好友正在听、公开个人主页。
- 房间协作者、共同编辑队列、表情/回复、在线状态。
- 评论热度排序、楼中楼折叠、@用户和通知中心。
- PWA、媒体快捷键、Media Session、移动端适配。
- AI 根据自然语言检索歌曲，生成歌单草稿，经用户确认后保存。

### 5.3 P2（演进）

- Agent 工具调用、RAG 音乐知识库、长期偏好记忆和可解释推荐。
- 多数据源匹配与降级、跨平台歌单导入。
- 公开主题房、定时房、房间回放摘要。
- 高级推荐、收听统计、年度报告、桌面端封装。

### 5.4 明确不在 MVP

- 自建或上传受版权保护的音乐文件。
- 离线下载、破解会员/地区限制、绕过第三方鉴权。
- 语音聊天室、直播推流、房间内音频转发。
- AI 自主发布评论、私信用户或未经确认修改正式歌单。
- 支付、会员体系和商业广告。

## 6. 核心功能需求

### 6.1 账户与身份

#### 用户故事

- 用户可以通过邮箱/用户名注册并登录 TMusic。
- 用户可以在多设备保持会话，并主动退出当前或全部设备。
- 用户可以选择绑定网易云账号；绑定失败不影响 TMusic 基础功能。

#### 业务规则

- 密码必须使用可靠哈希算法存储；访问令牌短时有效，刷新令牌轮换并可撤销。
- WebSocket 握手复用 TMusic 身份，不在 URL 查询参数中暴露长期令牌。
- 网易云 Cookie/令牌必须加密保存或仅保存在受控会话中，日志中必须脱敏。
- 网易云接入首期只采用二维码绑定，不接收或保存网易云手机号、邮箱密码；TMusic 登录身份与网易云账号绑定相互独立。
- 游客本地队列可在登录后选择合并，不静默覆盖云端队列。

### 6.2 内容发现与搜索

- 首页包含推荐区、排行榜、新歌/新专入口和最近播放。
- 搜索支持歌曲、歌手、专辑、歌单；保留关键词、类型、页码和筛选状态。
- 输入防抖建议 250–400 ms；空关键词展示搜索历史/热搜，不发送无意义请求。
- 支持错别字或拼音的智能搜索放在 P1；MVP 首先使用网易云结果并做统一映射。
- 列表项必须能播放、加入队列、收藏、加入歌单、分享和查看详情。

### 6.3 播放器

#### 状态模型

- 当前歌曲、队列、当前索引、播放状态、当前位置、音量、静音、循环模式、音质、来源上下文。
- 播放状态由前端 Audio Engine 管理；服务端记录必要行为，不按秒写播放进度。
- 队列和偏好本地即时保存，登录用户异步同步云端。

#### 播放规则

- 支持顺序、列表循环、单曲循环、随机播放。
- 切歌前解析临时播放 URL；不得把过期 URL 持久化到歌单或歌曲文档。
- 临时播放 URL 也不得写入浏览器持久化队列、日志或房间广播；前端持久层只保存 `provider + sourceId`。
- URL 失效时刷新一次；仍失败则标记原因并按用户设置跳至下一首。
- 歌曲不可用、需会员、地区受限、接口超时必须展示不同错误文案。
- 自动播放受浏览器策略限制时，显示明确的“点击继续播放”操作。
- 歌词按时间轴同步；无歌词时显示空状态，纯音乐不能视为错误。

### 6.4 个人音乐库与歌单

- 喜欢/取消喜欢歌曲，结果即时反馈并支持失败回滚。
- 创建歌单时填写名称、简介、封面和公开性；名称 1–50 字。
- 歌单创建者可增删歌曲、拖拽排序、编辑信息和删除歌单。
- 同一歌曲默认不可在同一歌单重复；未来可增加允许重复开关。
- 删除歌单和批量移除歌曲属于高风险操作，必须二次确认。
- AI 创建的结果先进入“草稿歌单”，用户确认后才写入正式歌单。

### 6.5 一起听

#### 房间模型

- 房间分为公开、口令和仅邀请三种加入策略。
- 每个房间只有一个房主，可以有多个协作者；默认只有房主能改变播放状态和队列。
- 房间中的音频仍由每个客户端从音乐源独立拉取，服务端只同步控制状态，不转发音频。
- Redis 保存活跃房间状态、成员在线状态与心跳；MongoDB 保存房间元数据、聊天历史和必要审计数据。

#### 创建与加入

1. 用户创建房间，设置名称、可见性、人数上限和是否允许协作者点歌。
2. 服务端返回短码和分享链接。
3. 加入者通过 REST 获取房间快照，再建立 WebSocket 连接并发送 `room:join`。
4. 服务端校验权限后返回权威播放状态、队列版本、成员列表和最近消息。
5. 客户端解析歌曲 URL，在准备完成后上报 `room:ready`，再按估算时间开始播放。

#### 同步协议

- 服务端维护单调递增的 `stateVersion`，状态至少包含 `trackId`、`isPlaying`、`positionMs`、`serverTime`、`startedAt`、`queueVersion`。
- 播放中的理论位置为 `positionMs + (当前服务端时间 - startedAt)`；暂停时位置固定。
- 客户端通过 ping/pong 估算服务端时钟偏移和网络往返时延。
- 偏差小于 300 ms：不处理；300–1500 ms：短时微调播放速率；大于 1500 ms 或发生切歌：直接 seek。
- 所有控制命令携带 `commandId` 和客户端已知 `stateVersion`；服务端鉴权、去重并生成新版本后广播。
- 客户端忽略低版本事件；版本断档时请求完整快照。
- 房主断线后保留 30 秒；逾期按进入顺序移交给协作者或普通成员，无成员则关闭房间。具体时长可配置。

#### 房间聊天

- 支持文本、表情和歌曲卡片；MVP 不支持文件与图片上传。
- 建房时可选 `PERSISTENT` 或 `EPHEMERAL`：持久模式写入 MongoDB 并按保留期清理；临时模式只放 Redis 与客户端内存，在房间结束或最后成员退出时立即删除，并设置兜底 TTL。
- 临时模式下，单个成员退出只清除其本地聊天缓存，不影响仍在房间成员的本场消息；“退出一起听即删除”以整场房间会话结束为边界。
- 消息发送采用客户端临时 ID，服务端 ACK 后替换为正式 ID，防止重复显示。
- 历史消息游标分页；新成员默认只拉取最近 50 条。
- 单条文本 1–500 字；需做频控、XSS 清洗、敏感内容治理、拉黑/禁言预留。
- 聊天消息和播放控制是不同事件流；聊天拥塞不得阻塞播放同步。

### 6.6 评论区

- 评论目标首期支持歌曲和 TMusic 歌单，提供 `TMusic 评论` 与 `网易云评论` 两个明确标注来源的 Tab。
- TMusic 评论存储在 MongoDB，支持发布、回复、点赞、删除与举报；网易云评论通过 Provider 实时/短期缓存读取，MVP 只读，不代理发布、回复或点赞。
- 支持一级评论和回复；内部以 `rootId` + `parentId` 表示线程，展示层可限制为两层。
- 排序支持最新和最热；热度由点赞、回复、时间衰减计算，算法可调整。
- 用户可删除自己的评论；管理员删除需记录理由。删除有回复的评论显示“该评论已删除”占位。
- 支持点赞/取消点赞、举报；同一用户对同一评论只能有一个有效点赞/举报状态。
- 两类评论使用独立游标与排序，不跨来源强行按点赞热度混排；网易云评论必须标记来源，不能伪装成本地评论。

### 6.7 AI 模块

#### MVP UI 与交互

- 登录后所有主页面右下角显示悬浮 AI 球；播放全屏页需避让播放控件。
- 空闲状态为低频呼吸波纹，生成中加快跳动，错误时短暂变色；尊重系统“减少动态效果”设置。
- 点击后桌面端打开侧边面板，移动端打开全屏对话页；支持进一步跳转到独立 `/ai` 页面。
- 支持新建会话、历史会话、发送/停止生成、重新生成和流式文本展示。
- AI 回答可包含标准化歌曲、专辑、歌手和歌单草稿卡片；卡片操作仍走正式业务 API。

#### Agent/RAG 演进边界

- 模型供应商通过 `AIProvider` 适配层接入；业务不得绑定单一厂商响应结构。
- RAG 知识库建议包含歌曲/歌手/专辑元数据、风格标签、编辑知识和已获授权内容；不得擅自抓取或存储受版权保护的完整歌词。
- Agent 工具至少预留：`search_tracks`、`get_track_detail`、`get_user_taste`、`create_playlist_draft`、`add_tracks_to_draft`、`publish_playlist_draft`。
- 读取用户喜好需要明确授权；敏感用户数据不进入公共向量库。
- 所有写操作在服务端鉴权，发布歌单等操作要求用户确认；记录工具调用审计。
- 推荐结果须说明依据，并对不存在、不可播放或来源不确定的歌曲做校验。

### 6.8 通知与在线状态（P1）

- 通知类型包括评论回复、点赞、房间邀请、房主转移和系统通知。
- 在线状态是短期状态，存 Redis 并设置 TTL；不以 MongoDB 的 `isOnline` 字段作为事实来源。
- 用户可关闭“展示正在听”和房间邀请。

### 6.9 管理能力

- 用户状态管理：正常、禁言、封禁。
- 评论/聊天举报处理，支持隐藏、删除、驳回和审计。
- 查看第三方音乐源健康度、缓存命中率、WebSocket 在线数和异常房间。
- 管理端操作必须采用 RBAC 并写不可变审计记录。

## 8. 推荐技术架构

```text
React Web / PWA
  ├─ REST/JSON ───────────────┐
  ├─ SSE（AI 流式输出）       │
  └─ WebSocket（房间/聊天）   │
                              ▼
Node.js API（TypeScript，模块化单体起步）
  ├─ Auth / User / Library / Playlist
  ├─ Catalog / Music Provider Adapter
  ├─ Room / Chat / Comment
  ├─ AI Gateway / Agent Tools
  └─ Admin / Audit
        ├─ MongoDB：持久业务数据
        ├─ Redis：缓存、限流、在线状态、房间状态、Pub/Sub
        └─ NetEase Provider：元数据、歌词、临时播放地址
```

建议前端使用 React + TypeScript + Vite、TanStack Router/Query、Zustand、Howler.js 或原生 Audio 封装、Socket.IO Client。后端使用 Node.js + TypeScript，可选 NestJS 或 Fastify；实时层建议 Socket.IO + Redis Adapter。MVP 采用模块化单体，等房间或 AI 压力独立增长后再拆服务。

### 数据职责

| 存储 | 保存内容 | 不应保存 |
| --- | --- | --- |
| MongoDB | 用户、歌单、评论、消息、会话元数据、审计、第三方 ID 映射 | 短期播放 URL、高频心跳、每秒播放位置 |
| Redis | 房间权威状态、在线成员、分布式锁、热点缓存、限流计数、Pub/Sub | 唯一永久数据副本 |
| 浏览器 | 队列快照、音量、主题、短期缓存 | 长期密钥、其他用户敏感数据 |

## 10. 非功能需求

### 10.1 安全与隐私

- 全站 HTTPS；Cookie 使用 `HttpOnly`、`Secure`、合适的 `SameSite`。
- 输入统一校验，富文本默认禁用；输出转义，防止 XSS、NoSQL 注入和原型污染。
- REST、登录、评论、聊天、建房和 AI 分级限流。
- 日志不记录密码、完整 Cookie、访问/刷新令牌、模型密钥和私人消息正文。
- 提供账户数据导出/删除能力的接口预留；删除策略区分匿名化与硬删除。
- AI 防提示注入、工具白名单、参数校验和服务端权限复核。

### 10.2 可用性与性能

- 第三方 API 设置超时、熔断、有限重试和缓存；禁止无限重试。
- 搜索结果、歌曲元数据和歌词可缓存；播放 URL 只按实际有效期短缓存。
- WebSocket 网关无状态扩容，使用 Redis Adapter 跨实例广播。
- MongoDB 为评论游标、消息游标、用户歌单、唯一点赞建立复合索引。
- 首页和列表使用骨架屏；所有异步状态包含 loading、empty、error、retry。

### 10.3 可观测性

- 统一 `requestId`、`traceId`、`userId`（脱敏）和错误码。
- 指标覆盖 API 延迟/错误、第三方源延迟/错误、WS 连接/重连、同步漂移、Redis/Mongo 健康、AI 首 token 时间与消耗。
- 房间状态变更记录结构化事件，但不记录高频心跳全文。

### 10.4 可访问性与兼容性

- 键盘可完成播放控制与对话操作；关键控件具备可读标签和焦点状态。
- 颜色对比符合 WCAG AA；AI 波纹与播放器动画支持减少动态效果。
- 支持最近两个主版本的 Chrome、Edge、Firefox、Safari；移动端覆盖主流 iOS Safari 和 Android Chrome。

### 10.5 合规

- 网易云及其他第三方源必须经过授权与条款核查；不得将未授权公开 API 等同于商业可用授权。
- 不代理绕过付费、版权、地区或登录限制；不可用内容明确告知用户。
- 封面、歌词、音频与用户内容分别标记来源、权利和缓存策略。
- 上线前必须完成隐私政策、用户协议、内容举报与版权投诉流程。

## 11. 验收场景

### 11.1 播放闭环

1. 用户搜索歌曲并点击播放。
2. 播放器在成功、不可用、超时情况下均给出确定状态。
3. 用户拖动进度、切歌、切换模式，刷新页面后保留合理队列和偏好。

### 11.2 一起听

1. A 创建邀请房，B 通过链接加入。
2. B 加入后 3 秒内看到房间快照并开始与 A 同步播放。
3. B 默认无法切歌；A 切歌后 B 收到新版本并播放同一歌曲。
4. B 发送消息只出现一次；断网重连后补齐消息并恢复当前进度。
5. A 离线超过宽限期，房主按规则转移；所有客户端状态一致。

### 11.3 评论

1. 用户发布、回复和点赞评论，计数一致且重复请求不重复计数。
2. 删除带回复的根评论后回复链仍可阅读，根节点显示删除占位。
3. 被禁言用户不能发送评论或房间消息，但仍可播放允许的内容。

### 11.4 AI

1. 用户点击悬浮球进入 AI 页，发送消息并看到流式响应。
2. 中途停止后消息状态明确，可重新生成。
3. AI 返回歌单草稿时，用户确认前不创建正式歌单。
4. 推荐中的每首歌曲都经过 Provider 校验，不可播放项有标识或被替换。

## 13. 待产品确认

1. 当前已确认仅供个人学习；若未来公开或商业上线，必须重新评估网易云源授权、隐私和内容治理方案。
2. MVP 登录采用邮箱密码、手机验证码还是第三方 OAuth？
3. 一起听默认由房主独占控制，还是所有成员都可点歌？本文默认房主独占、可授权协作者。
4. 持久房间聊天记录默认保留多久？本文建议 30 天；临时模式已确定在房间会话结束时删除。
5. 已确定支持网易云评论或自有评论区；本文采用双 Tab，网易云评论 MVP 只读。
6. AI 首期使用哪个模型服务、是否允许匿名试用、每用户额度是多少？
7. 是否需要桌面端或移动原生端？本文默认先做响应式 Web/PWA。
